# GT-P5100: подготовка облачной сборки

Это файлы для GitHub Actions, НЕ прошивка и НЕ установочный ZIP для TWRP.

Первый этап — скомпилировать исходное ядро, прежде чем менять сон или память. Он проверяет доступность исходников, ARM-компилятора и совместимость старой сборки с сервером. Успешная компиляция не доказывает побайтовую воспроизводимость исходного boot.img или работоспособность на планшете.

## Что зафиксировано

- Ядро MightyM17, коммит 4f4a4b2427c5b09ec0442c0578957322ff4c7ca6; короткий SHA совпадает с версией ядра исследованного ROM.
- AOSP ARM GCC 4.9, коммит cb7b3ac1b7fdb49474ff68761909934d1142f594, найденный через тег android-9.0.0_r1. Это выбранная версия компилятора, а не доказанная точная копия компилятора автора ROM.
- Исходный espresso_defconfig без включения zRAM, изменения частот или драйверов.
- Действия checkout/upload-artifact закреплены за SHA. Пакеты ОС устанавливаются из репозиториев Ubuntu, поэтому весь образ сервера не является побайтово воспроизводимым.

## Как запустить

1. Нужен отдельный публичный репозиторий GitHub, например p5100-android9-build. Не загружать туда резервные копии планшета, EFS, личные логи, ROM или закрытые аппаратные библиотеки.
2. Разместить содержимое этой папки в корне репозитория, включая скрытую папку .github. В GitHub подключении разрешить доступ к этому репозиторию.
3. На вкладке Actions выбрать `GT-P5100 kernel baseline - NOT FLASHABLE`, затем `Run workflow`. Запуск только ручной; push, PR и расписание не запускают сборку.
4. После завершения скачать артефакт и проверить result.json. При неудаче артефакт содержит журнал, а не готовое ядро. Сохранение результатов — 3 дня.

Стандартный ubuntu-22.04 runner для публичного репозитория не требует платного compute. В private репозитории job намеренно пропускается. Для артефактов действуют ограничения GitHub; никаких larger runners или платных подписок эта конфигурация не заказывает. Источник: https://docs.github.com/en/actions/reference/runners/github-hosted-runners

## Что будет получено

Журнал, конфигурация, версии инструментов и исходников, контрольные суммы; при успехе — zImage, Module.symvers, kernel.release и модули из дерева ядра. Отдельные модули PowerVR здесь не собираются. boot.img, system.img, полный Android и ZIP для TWRP не создаются.

НЕЛЬЗЯ прошивать zImage.NOT-FLASHABLE в раздел KERNEL/BOOT. Для установочного кандидата нужны совместимые модули, упаковка boot.img с ramdisk, проверка размера и разметки, резервная копия и откат. Первое облачное ядро не содержит исправления сна.

## Следующие этапы

1. Разобрать фактический результат облачной компиляции. Старый код может потребовать отдельных исправлений совместимости host-инструментов; их нужно документировать.
2. Подготовить и проверить изменения libsuspend. Проблема выбора обработчиков — отдельная задача userspace; сборка ядра её не исправляет.
3. Для заменяемых библиотек определить точный ABI и зависимости Android 9. Воспроизвести базовую сборку библиотеки до изменения поведения. Стандартных 14 ГБ диска runner может не хватить для полного дерева AOSP, поэтому обещания полной сборки здесь нет.
4. Только после этого создавать тестовый установочный пакет с проверкой SHA исходных файлов, возможностью отката и испытаниями на GT-P5100.

## Что уже проверено локально

Существование закреплённых коммитов ядра/компилятора, формат конфигурации и синтаксис Python. Linux-компиляция и GitHub Actions ещё не выполнялись. Исходная прошивка не изменена.
